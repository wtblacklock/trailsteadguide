## 2. Fixed

### Factual corrections (2 guides, 5 places)

**1. California applied Yosemite's exception to the whole state.**
`app/guides/camping-in-california-for-beginners/page.tsx` stated that federal sites reserve
through recreation.gov "5 months out at 7am Pacific" as a blanket rule covering Yosemite,
Sequoia & Kings Canyon, Joshua Tree, Death Valley, Pinnacles, Lassen Volcanic and Redwood. Only
Yosemite works that way. The 2026-09-03 audit flagged this and left it alone because it could
not be confirmed without opening the agency pages; it is now corroborated from two independent
directions:

- The standard is a **6-month rolling daily release at 7am PT / 8am MT / 10am ET**
  ([Recreation.gov's own reservation tips](https://www.recreation.gov/articles/list/tips-for-making-campsite-reservations-at-popular-locations/281)),
  and Joshua Tree specifically books on that rolling 6-month window at 7:00 AM Pacific
  ([Joshua Tree campground booking](https://www.nps.gov/jotr/planyourvisit/permitsandreservations.htm)).
- Yosemite is the documented exception: Upper/Lower/North Pines, Wawona and Hodgdon Meadow
  release **a full month of inventory at once on the 15th, five months ahead, at 7am PT**
  ([NPS Yosemite campground reservations](https://home.nps.gov/yose/planyourvisit/camping.htm)).

Corrected in four places, and the correction preserves the specific numbers rather than
retreating to vaguer language:

- the reservations bullet list (now: 6 months out at 7am Pacific rolling, with Yosemite's
  15th-of-the-month block release named as the exception),
- the "National parks and federal lands" body paragraph (same),
- the `QuickAnswer` summary,
- the common-mistakes item, which had said Yosemite Valley *and* Big Sur both sell out "six
  months out" - now "six months out for Big Sur, five for Yosemite Valley".

The page's JSON-LD `faqPageGraph` entry and its visible FAQ answer both concern **state** parks
(ReserveCalifornia, 6 months, 8am Pacific), which is correct and unaffected, so page and
structured data still agree. The JSON-LD FAQ's one federal sentence was already correctly scoped
to Yosemite only and was left untouched.

**2. Utah asserted a booking window that does not exist.**
`app/guides/camping-in-utah-for-beginners/page.tsx` recommended state parks because they "do not
require you to win a booking race twelve months out". No system in the comparison runs a 12-month
window: recreation.gov is 6 months (source above), and Utah's own state parks are a **4-month**
rolling window for individual sites (11 months only for group sites)
([Utah State Parks](https://stateparks.utah.gov/resources/policies-and-park-rules/)). Changed to
"six months out", which makes the contrast accurate in both directions - the state-park
alternative really is the shorter, easier window.

### The dash grep in the brief silently fails in this sandbox

Process note for whoever runs this next. The brief's recommended
`grep -P '\x{2014}|\x{2013}'` **errors out** in this container with
`character code point value in \x{} or \o{} is too large`, because grep runs under a non-UTF-8
locale where `\x{}` above `0xFF` is invalid. If stderr is redirected - as it naturally is when
excluding noise - it produces empty output that looks exactly like a clean result. This audit's
first pass hit precisely that and briefly recorded a false "clean". The scan was redone with a
Python codepoint scan over `app/`, `components/`, `lib/`, `data/`, which is what the 0-violation
result above is based on. Recommend the brief switch to that, or prefix `LC_ALL=C.UTF-8`.

## 4. Blocked by sandbox

**Blocked is not clean.** No claim is made in either direction about anything in this section.

Every outbound host this audit needs is refused by the session's egress proxy with
`gateway answered 403 to CONNECT (policy denial)`. Confirmed this run by direct probe:
`www.nps.gov`, `www.recreation.gov`, `images.unsplash.com`, `www.amazon.com` - all return curl
code `000` and all four appear in the proxy's own `recentRelayFailures` log as
`connect_rejected`. `WebFetch` returns `EGRESS_BLOCKED` for the same hosts, so it is not a
fallback. `WebSearch` works and was the sole research tool for section 7.

Consequences:

- **248 external URLs unchecked** - 53 agency/reference links (NPS, state park systems,
  reservation portals), 148 Amazon/`amzn.to` affiliate links, the remainder YouTube embeds and
  Reddit citations. **Nothing was edited or removed on the strength of a failed request.**
- **175 distinct image URLs unchecked** - 90 Unsplash, 30 Wikimedia, the rest local/product
  images. **No image URL was changed**, and no photo ID was invented.
- **`npm run validate:affiliate` exits 1 with every link reported `[403]`.** These are proxy
  CONNECT denials, not Amazon responses - `www.amazon.com:443` is in the proxy rejection log. The
  script cannot tell the two apart, so **this run says nothing about affiliate-link health in
  either direction.** Do not read it as broken; do not read it as verified.

To restore these three checks, the environment's network policy needs `nps.gov`,
`recreation.gov`, the state park agency domains, `images.unsplash.com` and `amazon.com`
allow-listed. Until then this audit is repo-only plus WebSearch.
