## 3. Advisories left open

Both remaining items require a breaking major-version bump and were **not**
applied, per instructions to never use `npm audit fix --force` in this job.

- **extract-zip / @puppeteer/browsers / puppeteer-core** - high -
  https://github.com/advisories/GHSA-jmr9-qjv8-65gv,
  https://github.com/advisories/GHSA-7pqw-9j4j-h8q3.
  Fix requires `puppeteer-core@25.10.0` (current pin: `^24.43.1`, a major
  bump). **Reachability: not reachable in this codebase.** I read
  `lib/pdf/render.ts` - it always calls `puppeteer.launch()` with an explicit
  `executablePath` pointing at an already-installed browser
  (`@sparticuz/chromium` on Vercel, system Chrome locally). It never invokes
  `@puppeteer/browsers`' download/install path, which is the only code path
  that runs `extract-zip` against a (potentially attacker-controlled) zip
  archive. Low priority.

- **postcss (nested under `next`)** - high -
  https://github.com/advisories/GHSA-qx2v-qp2m-jg93,
  https://github.com/advisories/GHSA-6g55-p6wh-862q,
  https://github.com/advisories/GHSA-fxqj-rqcc-2cmp,
  https://github.com/advisories/GHSA-r28c-9q8g-f849.
  Next.js vendors its own internal `postcss@8.4.31` independent of the
  project's top-level `postcss` devDependency (which is already patched to
  8.5.28). Fixing the nested copy requires `next@16.3.4`, a major bump.
  **Reachability: build-time only.** This `postcss` copy is used by Next's
  internal CSS build pipeline, processing this site's own authored CSS at
  build time - not attacker-controlled CSS/source maps at request time. Low
  priority.

## 5. Deferred to a human

- **next 15.5.25 → 16.3.4** (major). Closes the remaining nested-postcss
  advisory. Next 16 changes its caching/rendering model (Cache Components)
  and drops some deprecated APIs; this site has ~100 static/SSG routes plus
  dynamic `trip-pack` routes and would need a full manual regression pass
  (build, routing, metadata, `next.config.ts`) before adopting.
  `eslint-config-next` should move in lockstep (16.3.4 is out now).
- **puppeteer-core 24.43.1 → 25.10.0** (major). Closes the extract-zip
  advisory (currently assessed as unreachable, see above). Puppeteer major
  bumps have historically changed default launch behavior and dropped
  deprecated `Page`/`Frame` APIs; also needs `@sparticuz/chromium`
  compatibility checked, since that package pins to specific
  puppeteer-core/Chromium protocol versions. Should be validated against
  `lib/pdf/render.ts` and the `trip-pack-flow` integration test specifically.
- **tailwindcss 3.4.19 → 4.x**. Tailwind v4 changes the config format
  (CSS-first config, no more `tailwind.config.js` by default) and the
  PostCSS plugin package name. Requires a dedicated migration pass across
  all component/utility classes.
- **eslint 9.39.5 → 10.x**, **typescript 5.9.3 → 7.x**,
  **@testing-library/jest-dom 6.9.1 → 7.x**: left alone since none were
  named as in-scope for this run and each is a tooling major bump; no
  advisories depend on them, so there's no security urgency.

The one failing test (`lib/pdf/__tests__/trip-pack-flow.test.ts`) fails with
`Browser was not found at the configured executablePath
(/usr/bin/google-chrome)`. Confirmed this is purely an environment gap, not
a code defect: `lib/pdf/render.ts` already honors `PUPPETEER_EXECUTABLE_PATH`
(its own comment says CI sets this via `setup-chrome`), and re-running with
`PUPPETEER_EXECUTABLE_PATH=/opt/pw-browsers/chromium npm test` passes all
387 tests. No source change was made for this, since the code already
supports the right fallback mechanism - this container just doesn't have
that env var set. No further action taken here.

`npm run validate:affiliate` was not treated as a meaningful signal per the
environment note: this session's egress proxy blocks essentially every host
that script would check (amazon.com, nps.gov, images.unsplash.com, and
trailsteadguide.com itself all return `403 policy denial`), so its failures
are proxy artifacts, not real broken links.
